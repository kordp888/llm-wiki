# LLM Wiki (한국어 요약)

> **sLLM과 에이전트가 수집·정제·연결·재사용을 24시간 수행하는 지식 생산 시스템. 사람 게이트 없이는 아무것도 나가지 않습니다.**

⚙️ 24시간 로컬 인프라에서 운영 중 — 테스트 500+개, 전체 5초
🌐 English version: [README.md](./README.md)

## 왜 만들었나

대부분의 개인 지식베이스는 "저장만 되고 죽는" 무덤입니다. 저는 **지식이 저장이 아니라 생산되는 시스템**을 원했습니다. 자는 동안에도 새 정보를 수집하고, 분석하고, 구조화해서 기존 지식과 연결하는 시스템. 그리고 클라우드 API 의존 없이 **로컬에서** 돌아가는 시스템.

## 한 문장 설계

> 뉴스를 모으고 → 사람이 폰에서 고르고 → 고른 것만 조사 산출물이 되고 → **그 무엇도 자동으로 공개되지 않는다.**

전 구간의 원칙은 **"모델 출력은 아무것도 승인하지 않는다"** 입니다. 사실 판정·경보·핸드오프·공개는 전부 사람 게이트를 지납니다.

## 하루 흐름

```
07:00  수집     수집 → 중복제거 → 채널 적합성 판정(로컬 sLLM) → 검토 파일
07:03  제안     엔티티 후보 순위 → 검토 파일에 승인 대기 행 주입
07:05  발행     검토 파일 → 모바일 볼트 (단방향, 탭 가능한 체크리스트)
08:00  체크인   건강 판정 + 오늘 할 일 → 텔레그램

       … 사람이 폰에서 항목을 체크 …

21:25  회수     모바일 체크 → 위키 (가산 전용: [ ]→[x] 만)
21:27  반영     체크된 엔티티 → 승인 레지스트리
21:28  이벤트   승인 엔티티로 이벤트 결합 + 클라우드 조망
21:30  체크인   저녁 건강 판정 → 텔레그램
21:35  조사     체크된 뉴스 → Fact Pack · Content Brief · 큐
```

## 지능 계층

비용 정책이 곧 배치 규칙입니다. 종량제 API는 **기본 비활성** — 플래그 없이는 호출 자체가 안 됩니다.

| 계층 | 수단 | 역할 |
|---|---|---|
| 1 결정론 | 해시·정규식·스코어링 | 중복제거 · 채널 스코어 · 모순 탐지 |
| 2 로컬 sLLM | Qwen · Gemma · EXAONE · DeepSeek | 적합성 판정 · 초안 · 에이전트 대화 |
| 3 구독 클라우드 | 1M 컨텍스트 모델 | 일괄 조망 |
| 4 종량제 | 플래그 게이트 | 명시 활성화 전에는 없음 |

## 안전 구조 — 전부 실제 사고에서 나왔습니다

- **가산 전용 동기화** — 모바일 체크는 `[ ]`→`[x]` 만 전파. 양방향 미러가 모바일측 삭제를 전파해 171개 파일을 지운 사고 이후, "병합을 잘하기"가 아니라 **파괴 신호를 표현 불가능하게 만드는 것**으로 해결했습니다.
- **사람 게이트 3종** — 엔티티 승인, 엔진 핸드오프, 데이터 엔진 활성화. 게이트 없이는 경고가 아니라 **구조적으로 진행 불가**입니다.
- **주입 방어 4단 골격** — 신뢰 경계 선언 → 지시 실행 금지 → 출력 스키마 고정 → 격리 데이터 마지막. 그리고 프롬프트만 믿지 않고 반환값을 코드로 검증합니다.
- **exit 0 은 성공이 아니다** — 크론 3건이 전부 `ok`인데 산출물이 0이었던 날 이후, 건강 판정은 프로세스가 아니라 **산출물 수치**만 봅니다.
